# ADR 0007: stage-scoped tool access and bounded review

- Status: accepted
- Date: 2026-10-18

## Context

Stage 3 introduced deep review stages and an optional LLM review call. Prompt
instructions alone do not prevent a reviewer or verifier from editing the
workspace, and a provider that never reports token usage could bypass a token
budget. Review also needs a bounded provider call.

## Decision

1. Add `ToolAccess::{Full, ReadOnly, VerifyOnly}` to the policy layer. The agent
   evaluates tool requests through `PolicyEngine::evaluate_with_access` before
   invoking any tool.
2. Explorer, planner and implementer use `Full`. Reviewer uses `ReadOnly`,
   which allows read/grep/glob and read-only git operations but denies edits,
   shell, git writes and plugins. Verifier uses `VerifyOnly`, which additionally
   allows a small allowlist of test/build/lint and read-only git commands.
3. Keep the pre-review workspace fingerprint as a second protection. It detects
   out-of-band changes made by a provider or a tool that bypasses the policy.
4. Run the optional review-model call through a bounded wrapper. The wrapper
   polls a cancellation token, enforces `review_timeout_secs`, cancels the
   provider, joins its worker within a bound, and returns an
   `llm-review-unavailable` finding instead of blocking the request.
5. When a provider reports no token usage, estimate tokens conservatively from
   the request and response (characters divided by three, rounded up). Token,
   stage, tool-call and wall-clock limits remain active.

## Consequences

- Reviewer and verifier tools are denied before execution, not only after the
  workspace changes.
- The fingerprint remains useful against providers or future tools that bypass
  the normal tool path.
- Review requests are bounded even when a provider ignores cancellation.
- Usage-less providers can no longer avoid token budgeting.
- The verification shell allowlist is intentionally narrow; new verification
  commands must be added explicitly.
